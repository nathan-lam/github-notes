


Code should be easy to read and follow



# Do's
- The code should explain itself
	- if there is an assumption, it should be stated
	- A new developer should be able to understand what is happening
- There should be a clear line of logic
	- information should flow through a mainline (think water flowing through pipes)
		- different cases should ideally merge back into the main line of logic
		- it is easier to handle 1 case than 16 slightly different cases
